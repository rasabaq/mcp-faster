// what it does

stats

shows sessions, idle time, drops, failed connects, tool errors and tokens for every server.npx mcp-faster stats

bench

runs the same tasks all upfront, with tool search, in code mode and on a local mirror.npx mcp-faster bench

proxy

sits in front of any server. it merges tools that always run together, caches results, sends back smaller results, and starts a server only when the first call needs it.npx mcp-faster proxy --config proxy.json

mine

finds tool calls that always come in a chain, and proposes one tool for each chain.npx mcp-faster mine

local

everything runs on your machine. it reads the logs that are already there. there is no account and no upload.

// questions

what does mcp-faster stats read?

the Claude Code logs and chat records that are already on your computer. for this page that was log files and chat records from one machine.

what is the heat score?

heat = connects × stays up × gets used × few errors

four checks, each from 0 to 100%, multiplied together. one weak check pulls the whole score down on purpose. a server that never connects is not healthy, however fast it is.

what do the labels mean?

each server gets one label: its biggest problem. the checks run in this order.

    what does the proxy do?

    it sits between your agent and your servers. it has three layers: consolidate, cache and compact. it can also start a server only when the first call needs it. you set it up in proxy.json.

    what do I need to run it?

    Node 24 or newer. stats and mine only read your logs. bench calls a real model, so it needs a model API key.
